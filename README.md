# Parking BLE Test

Тестовый стенд: **ESP32-C3 SuperMini (PlatformIO)** + **Android BLE Probe (Java)**.

## Получить APK

Откройте **Actions → Build Android test APK → последний успешный запуск → Artifacts → ParkingBLEProbe-debug-apk**. Архив содержит `app-debug.apk`, устанавливаемый на Android 8.0+ (API 26+). Если запуск неуспешен — сначала проверьте его лог.

## Прошить ESP32-C3

1. Откройте папку `esp32` в VS Code + PlatformIO.
2. Выберите окружение `esp32c3_supermini`, выполните Build → Upload.
3. При необходимости загрузки переведите ESP32-C3 в режим BOOT (зажмите BOOT, коротко нажмите RESET, отпустите BOOT).
4. Serial monitor 115200 покажет `ParkingBLE advertising started`.

Маяк передаёт BLE Service UUID `c6ec1c8d-e23a-4751-93f8-31d4d4a17b10` с рекламным интервалом 160 мс.

## Тест приложения

1. Установите APK, включите Bluetooth и геолокацию, выдайте запрошенные разрешения.
2. **Живой RSSI-тест** — показывает принятый RSSI при открытом экране.
3. Остановите живой тест, выберите **Запустить ФОН: FOUND / LOST**.
4. Погасите экран, отойдите от маяка, затем приблизьтесь.
5. Откройте приложение и экспортируйте CSV. Если `FOUND` не приходит, попробуйте фоновый режим `ALL_MATCHES`.
6. На Android 10/11 для фонового обнаружения нужно вручную разрешить геолокацию **«Всегда»**.

### Поля CSV

`timestamp,mode,event,rssi_dbm,dispatch_delay_ms`.

`dispatch_delay_ms` — системная задержка от момента приёма BLE-пакета до получения callback приложением, **не** полная задержка от пересечения автомобилем 5-метровой границы.

## Ограничения

Диагностическое ПО **не открывает шлагбаум и не обращается к серверу**. Фоновое сканирование зависит от прошивки смартфона и настроек энергосбережения. После принудительной остановки приложения Android может не доставлять события до повторного ручного запуска. Расстояние нельзя надёжно вывести из RSSI без калибровки.

Этот проект не является сертифицированной системой контроля доступа.
